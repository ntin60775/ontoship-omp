# Контракт: свежий потребитель доходит до зелёного deploy-check

## Порядок выполнения

- **После** `deploy-check-marketplace-paths`: приёмка этого плана заканчивается зелёным
  `deploy-check`, а красный в плагинной установке чинит тикет 02 того плана.
- **После** `kb-docs-vs-plugin-delivery`: оба плана правят `docs/ops/deploy-ontoship.md`;
  тот план описывает канал доставки, этот — дописывает в него сценарий «с нуля».
- **Последний в очереди**: от него не зависит ни один план. `payload-refs-undelivered-docs`
  и `registry-and-version-in-consumer` с ним не связаны.

## Goal

Проект, поставивший плагин маркетплейса и ничего больше, доходит до `deploy-check`
`exit 0` без ручной сборки entry point: пакет даёт идемпотентную инициализацию, которая
создаёт или обновляет управляемый блок в `AGENTS.md` проекта, приводит `.gitignore` к
требованиям правил и передаёт работу `/onto-doc`. Плагин доставляет только `.omp/` —
проектные файлы он не пишет и не затирает; инициализация запускается человеком и только
по проекту.

## Done

- Зафиксировано решение: отсутствие entry point у потребителя закрывается командой
  инициализации **в payload** (`commands/init.md`), а не требованием к проекту. Шаблон
  блока едет файлом внутри payload (`.omp/templates/`), не в `docs/` пакета.
- Команда работает **секцией, а не файлом**: управляемый блок между маркерами
  `<!-- BEGIN ontoship -->` … `<!-- END ontoship -->` (та же маркерная конвенция, что у
  реестра `inventory:*`). Поведение по случаям:
  - `AGENTS.md` нет — создаётся файл с блоком;
  - файл есть, блока нет — блок дописывается в конец, остальной текст не трогается;
  - блок есть и совпадает с шаблоном — ничего не делается (идемпотентность);
  - блок есть и отличается — содержимое блока заменяется, вне маркеров не меняется ничего,
    и печатается предупреждение: правки внутри блока не сохраняются, проектные правки
    вносятся вне маркеров;
  - маркеры непарные или битые — команда останавливается с явной ошибкой, ничего не угадывая.
- `--force` не нужен: секционная правка не затирает проектный текст, полная перезапись
  файла не выполняется никогда.
- Там же: в `.gitignore` дописываются только отсутствующие строки, которых требуют правила
  (`.gitmark/`, `*-map.html`, `.scratch/`), после чего команда зовёт `/onto-doc`.
- **Имена команд в блоке — с префиксом плагина** (`/ontoship:kb`, `/ontoship:onto-doc`,
  `/ontoship:ship`, …): в потребителе команды плагина доступны именно так. Короткие имена
  работают только там, где пакет лежит нативно (этот репо).
- Только `init`: команда `upgrade` (апгрейд плагина плюс реестр проектов
  `~/ontoship-projects.txt`) в этот план не входит — отдельный план, если понадобится.
- Проверка «с нуля»: чистая probe-папка → установка плагина → инициализация → `/onto-doc`
  → `deploy-check` `exit 0`; повторный запуск инициализации — no-op. Шаги описаны в runbook.
- KB синхронизирован: `docs/plans/README.md`, `gitmark lint` чистый, индекс пересобран.

## Scope

- Payload: `.omp/commands/init.md` (команда), `.omp/templates/**` (шаблон блока).
- `docs/ops/deploy-ontoship.md` — сценарий «с нуля».
- `docs/plans/README.md`.

Вне scope: поведение самого `deploy-check.sh` — план `deploy-check-marketplace-paths`;
доки README/architecture — план `kb-docs-vs-plugin-delivery`; команда `upgrade`.

## Constraints

- Идемпотентность: повторный запуск не меняет файл (блок совпадает с шаблоном); вне
  управляемого блока команда не пишет никогда; полная перезапись `AGENTS.md` не
  выполняется — ни флагом, ни режимом.
- Плагин остаётся доставкой только `.omp/`; проектные данные (`AGENTS.md`, `docs/`) —
  собственность проекта.
- Шаблон едет в payload: у потребителя нет `docs/` пакета, а `docs/ontology.md` создаёт
  `/onto-doc`, не инициализация.

## Context

Аудит 2026-09-14 (отчёт `.scratch/audit-plugin-install-2026-09-14.md`, вне KB):

- Каталог объявляет источник как `git-subdir` с `path: ".omp"` — в потребителя едут только
  `commands/ rules/ scripts/ skills/`; `AGENTS.md` и `docs/` не поставляются.
- В поставке 0.2.0 нет команд инициализации и апгрейда (архивный план `marketplace-delivery`
  репо-каталога, тикет 03 — `/ontoship:init` + `/ontoship:upgrade` — не доехал).
- `deploy-check.sh` считает отсутствие `AGENTS.md` критическим (`exit 1`) — значит свежий
  потребитель без entry point красный по построению, а создать его нечем.
- Прецедент «payload несёт свои файлы»: sibling-плагин `1c` в кэше маркетплейса везёт
  `AGENTS.md` и `package.json` в корне плагина.
- Плагинные потребители на машине (`sot-omp-marketplace`, `erp-demo`) вышли из миграции с
  уже написанным `AGENTS.md`; сценарий «с нуля» нигде не описан.
