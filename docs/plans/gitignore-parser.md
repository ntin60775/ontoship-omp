# Контракт: движок уважает .gitignore так же, как git

## Goal

Файлы, которые git игнорирует, не попадают в индекс KB и не выдаются в `search`.
Сейчас `parse_gitignore()` — рукописное подмножество, и в двух местах оно расходится
с git **молча**: правило с `/` и без хвостового слэша не попадает ни в один список, а
шаблон каталога с путём сохраняется в виде, который никогда не матчится. На реальном
проекте это дало индекс, на 74 % состоящий из мёртвой копии правил.

Правило, которое не поддержано, обязано быть **видимым**, а не исчезать.

## Done

- Список markdown берётся у git — `git ls-files -z -co --exclude-standard -- '*.md'` —
  тогда бесплатно работают вложенные `.gitignore`, `**`, негативные правила, якоря и
  глобальные excludes. Фолбэк на собственный обход остаётся: git может отсутствовать
  или каталог может не быть репозиторием.
- В фолбэке ни одно правило не теряется: правила с путём (`/.omp/plugins/`,
  `.omp/.backup-*`, `drafts/secret.md`) теперь **исполняются** (якорятся к корню), а
  то, что подмножество не умеет (`!`, `**`), печатается как `[WARN] gitignore:
  правило '<s>' не поддержано фолбэком (нет git) — файлы под него попадут в индекс`
  из `lint` и `index`. На основном пути (git) предупреждать не о чем: подмножество
  не задействовано.
- Тест воспроизводит отчёт: `.gitignore` с `build/`, `.omp/plugins/`,
  `.omp/.backup-*`, `drafts/secret.md`; индекс обязан содержать только `docs/live.md`.
  Тест падает до правки и проходит после — и на основном пути (git), и на фолбэке.
- На репозитории с каталогом `.omp/.backup-*/` (реальный случай `erp-demo`: 126
  файлов, 74 % индекса) файлов бэкапа в индексе нет.
- `skills/kb-search/SKILL.md` и `skills/kb-curate/SKILL.md` не обещают больше, чем
  делает движок: если подмножество где-то остаётся, это сказано явно.

## Scope

- `.omp/skills/kb-search/gitmark.py` — `parse_gitignore`, `iter_md`, вывод `lint`/`index`;
- `tests/test_gitmark.py` — репро-тест (основной путь и фолбэк);
- `skills/kb-search/SKILL.md`, `skills/kb-curate/SKILL.md` — оговорка про подмножество,
  если оно остаётся;
- `docs/services/gitmark-cli/README.md` — как движок получает список файлов.

Не входит: `.gitignore` потребителей, содержимое их репозиториев, поведение `map`.

## Constraints

- `stop-before-commit` — после тестов и ревью ран останавливается, коммит подтверждает
  оператор.
- Правка не должна менять выдачу `search` на репозиториях, где индекс и так чист:
  единственное допустимое изменение — исчезновение файлов, которые git игнорирует.
- `git` вызывается один раз на `index`, без сетевых операций и без записи в репозиторий;
  отсутствие git — не ошибка, а переход на фолбэк.

## Context

**Отчёт о баге** (2026-09-15, внешний, воспроизведён мной на движке **0.4.1**):
`git check-ignore` подтверждает, что все четыре пути игнорируются, а `gitmark index`
индексирует три из них. Единственный корректно исключённый (`build/b.md`) отсекается не
правилом, а внутренним `EXCLUDE_DIRS` — это и маскирует баг в простых репозиториях.

**Корень** (`.omp/skills/kb-search/gitmark.py`):

| Строки | Дефект |
|---|---|
| 86–89 | `elif "/" not in s` — правило с `/` и без хвостового `/` не попадает ни в `dir_pats`, ни в `file_pats`: `.omp/.backup-*`, `drafts/secret.md`, `.omp/RULES.md`, `.omp/mcp.json`, `src/cf/ConfigDumpInfo.xml` |
| 106 | `any(part in dir_pats for part in rel.parts[:-1])` — сегмент (`plugins`) никогда не равен `.omp/plugins`, поэтому путь-квалифицированные каталоги не исключаются никогда; работают только односегментные (`build/`, `vendor/`, `.gitmark/`) |
| 108 | `_wild_match(rel.name, f)` — файловые шаблоны сверяются только с базовым именем, вопреки семантике git |

**Влияние на реальных репозиториях** (замерено 2026-09-15):

- `erp-demo`: каталог `.omp/.backup-cutover-20260911-185000/` (126 файлов) давал
  103 файла / 619 чанков из 154 / 835 — 74 % индекса. `gitmark search "тестовый контур
  прогон"` возвращал на 2–3 местах копии правил из бэкапа вместо живых документов.
  Каталог удалён вручную, индекс пересобран: 51 файл. Обходной путь есть, но он не
  выводится из `.gitignore` и потому не защищает от повторения.
- `zupupr`: каталог `.omp/.backup-rules-20260911-170506/` (14 `.md`) на месте;
  `ontoship` там ещё не поставлен, поэтому ущерб отложен, но он проявится сразу после
  поставки.

**Почему это важно сейчас.** Политика `.gitignore` у потребителей
(`sot-omp-marketplace/docs/reference/consumer-repo-layout.md`) опирается ровно на те
правила, которые движок сейчас теряет: `.omp/skills/`, `.omp/commands/`, `.omp/scripts/`
— каталоги с путём (дефект 2), `.omp/.backup-*`, `.omp/RULES.md`, `.omp/mcp.json` —
правила с `/` без хвостового слэша (дефект 1). То есть защита от мусора в индексе
сейчас инертна, и это надо назвать прямо в gotcha.

**Отвергнутые варианты:** оставить парсер как есть и ограничиться предупреждением —
индекс продолжит набирать мусор, а `kb-first` будет отдавать агенту устаревшие копии
как первоисточник; расширять своё подмножество до семантики git целиком — это
переписывание gitignore-движка, тогда как `git ls-files` уже даёт нужную семантику
даром (остаётся только фолбэк для окружений без git).
