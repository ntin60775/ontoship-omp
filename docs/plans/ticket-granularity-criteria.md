# Контракт: критерии неделимой логической единицы в разбивке на тикеты

## Goal

Текущая разбивка на тикеты слишком крупная — единственный регулятор размера —
квиз оператора («too coarse / too fine»). Оператор вынужден сам замечать, что
тикет содержит две независимо проверяемые возможности, и просить split уже после
публикации.

Нужно: навык `mp-to-tickets` сам доводит разбивку до неделимой логической
единицы — до квиза. Квиз остаётся, но сигнал «too coarse» означает, что скилл
не отработал до конца.

## Done

- В `mp-to-tickets/SKILL.md` **шаг 2 «Draft vertical slices»** дополнен
  критериями гранулярности (интеграция в существующий шаг, не отдельный раздел):
  1. **Определение единицы:** одна проверяемая возможность со своим способом
     приёмки (синтетический тест или иной наблюдаемый факт).
  2. **Признаки ДРОБИТЬ:**
     - два и более независимых обещания;
     - приёмка требует механику, **не объявленную** в `depends_on` (необъявленная
       зависимость — тикет строит то, что проверяется только вместе с чужим);
     - не проверяется без построенных соседей, и зависимость не осознанно
       зафиксирована в `Blocked by`.
  3. **Признаки СЛИТЬ:** ничего нового сверх соседа.
  4. **Исключение:** wide refactor (expand–contract) — единица по определению,
     не дробится; критерии неделимости к нему не применяются.
  5. **Pre-publish дробление:** если тикет не проходит границу единицы на этапе
     черновика (до шага 4) — разбить до публикации, без `git mv`.
  6. **Post-publish дробление:** `git mv` для сохранения истории; перенумерация
     остальных файлов; переписывание всех ссылок (`depends_on`, `Blocked by`,
     таблица в README плана, тексты соседних тикетов); grep по каталогу плана
     на старые номера — должно вернуть 0.
  7. **Проверка зависимостей:** DAG без циклов. Метод: для каждого тикета A —
     A не в `depends_on` A, и нет пути A → B → … → A (транзитивная проверка).
     Три места фиксации зависимости сходятся: frontmatter `links.depends_on`,
     строка `Blocked by:` в теле, колонка `Blocked by` в таблице README плана.
- **Шаг 4 «Publish the tickets»** дополнен: в README плана — **таблица**
  (не «listing») с колонками `#`, `Title`, `Status`, `Blocked by`.
- Квиз сохранён, но его вопрос «Does the granularity feel right?» получает
  контекст: скилл уже применил критерии выше.
- `gitmark lint` чистый, `index` пересобран.

## Scope

- `.omp/skills/mp-to-tickets/SKILL.md` — шаг 2 (критерии гранулярности),
  шаг 4 (таблица в README), шаг 3 (контекст квиза).
- `docs/plans/README.md` — индексная строка этого плана.

Вне scope: изменение формата тикета (frontmatter, секции), добавление внешних
зависимостей, правка кода за пределами `SKILL.md`.

## Constraints

- Формат тикета (шаблон из `SKILL.md:88-121`) не меняется.
- Не добавлять внешние инструменты: проверка циклов и перенумерация описываются
  как инструкции внутри навыка.
- Адаптируются из `ticket-breakdown.md` (issue #5) только три секции:
  «Граница», «Дробление и перенумерация», «Зависимости: DAG». Остальные
  (формат тикета, приёмка разбивки, связь с процессом, чего не делать) —
  вне scope.
- `stop-before-commit` — ран доработки навыка.

## Решения грилла (2026-09-29)

- **Q1:** Интеграция в шаг 2, не отдельный раздел — агент применяет критерии
  во время черновика, не после.
- **Q2:** Признак ДРОБИТЬ — «приёмка требует механику, не объявленную в
  `depends_on`» (не «не проверяется без соседей» — это слишком широко).
- **Q3:** Wide refactor — явное исключение, не дробится.
- **Q4:** Таблица в README плана с колонкой `Blocked by` — добавляется в
  шаг 4 (текущий «listing» → таблица).
- **Q5:** Pre-publish дробление — до шага 4, без `git mv`.
- **Q6:** Метод проверки циклов — транзитивная: A не в `depends_on` A,
  и нет пути A → B → … → A.
- **Q7:** Адаптируются три секции: «Граница», «Дробление», «DAG». Остальные —
  вне scope.
