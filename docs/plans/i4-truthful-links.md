# Контракт: I4 говорит правду

## Goal

`gitmark lint` ловит битую ссылку там, где её видит читатель: в теле и в `links.*`
frontmatter, для `.md`, каталогов и любых файлов. Граф, поиск и индекс не меняются —
их резолв остаётся мягким ([решение о двух модах](../decisions/link-resolution.md)).

Восстанавливается поведение, принятое 2026-09-06 и потерянное вместе со снятием плоских
копий (`erp-main@ae1822a3f` → `0d54cc225`); в апстрим пакета оно не ушло.

## Done

- [x] ссылка тела, которую разрешает только basename-поблажка, даёт ERR I4;
- [x] битая frontmatter-ссылка любого из шести типов `LINK_KEYS` даёт ERR I4 с типом в
      сообщении (`битая frontmatter-ссылка documents: ../../nope`);
- [x] цель проверяется на ФС: каталог и файл кода (`../../src/x.bsl`) — тоже, не только `.md`;
- [x] title, обёртка `<…>`, `#якорь`, `:line`-селекторы и URL-кодирование срезаются до проверки;
- [x] путь, ведущий за корень репозитория, проверяется там, куда ведёт: KB читается в
      многорепозиторной раскладке, и ссылка на соседний репозиторий — рабочая, пока файл
      на месте (правило уточнено замером, см. «Состояние»);

- [x] онтология (обе копии) описывает I3/I4 так, как их проверяет код.

## Context

Спека — [решение о двух модах](../decisions/link-resolution.md). В 0.4.6 PR #1 оживил
парсер frontmatter (I3/I6 работают), PR #3 (S1) сделал линт строгим для `.md`-ссылок тела.
S2–S4 закрывают остаток: без них I4 был слеп к frontmatter и к не-`.md` целям — то есть
к тому классу, ради которого писался аудит.

**Следствие для потребителей:** линт становится строже, и пять KB машины получают ERR на
реальных битых ссылках. Это ожидаемая цена честного I4; починка — в самих KB
(`erp-main/docs/plans/kb-audit-2026-09/02-omp-paths.md` — ровно про пути `.omp/`).
