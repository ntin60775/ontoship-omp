# 03: Runbook развёртывания — плагинный канал и путь к скрипту

**What to build:** runbook этого репо описывает фактический канал доставки: установка
плагином маркетплейса, путь к скрипту проверки у потребителя, и команды, которые
человек может выполнить руками (реальный путь движка — в человеческой оболочке
`skill://` не резолвится).

**Blocked by:** 02 (runbook ссылается на поведение исправленного скрипта).

- [ ] `docs/ops/deploy-ontoship.md`: штатный канал — плагин маркетплейса
      (`install` / `upgrade`); ручное копирование `.omp/` помечено как локальный/legacy
      вариант, а не как основной путь
- [ ] Путь к скрипту у потребителя — плагинный
      (`.omp/plugins/node_modules/ontoship/scripts/deploy-check.sh`), с примером прогона
- [ ] Команды движка в runbook даны реальным путём (не `skill://`), либо заменены на
      команды агента (`/kb`, `/kb-map`)
- [ ] Семантика кодов возврата описана как в исправленном скрипте (включая то, что
      проверка ловит ссылки payload на несуществующий путь движка)
- [ ] ADR доставки — ссылкой на репо-каталог (`sot-omp-marketplace/docs/decisions/plugin-delivery.md`),
      без дублирования текста
- [ ] Строка про правило `ship-1c` в этом файле **не** трогается — это scope плана
      `kb-docs-vs-plugin-delivery`
- [ ] `docs/plans/README.md` актуален, `gitmark lint` чистый, индекс пересобран
