# 02: deploy-check.sh — самоотносительный корень, страж, смоук-поиск

**What to build:** `deploy-check.sh` одинаково верно оценивает и плоскую, и плагинную
установку: `exit 0` на здоровом потребителе, `exit 1` на реально сломанном — и он же
ловит регресс «payload снова ссылается на несуществующий путь движка», чтобы зелёный
результат нельзя было получить на пакете, чьи правила ведут в никуда.

**Blocked by:** 01 (проверка-страж по построению красная, пока payload не мигрирован).

- [ ] Корень пакета резолвится от собственного расположения скрипта; `$0`/`BASH_SOURCE[0]`
      абсолютизируется **до** `cd` в корень проекта (запуск из подкаталога резолв не ломает)
- [ ] От корня пакета проверяются только `skills/`, `commands/`, `rules/`; `AGENTS.md`,
      `docs/`, `.gitignore` — от корня проекта (плагин AGENTS.md не поставляет)
- [ ] Проверка-страж: литерал `.omp/skills/kb-search/gitmark.py` в пакетных
      `rules/`, `commands/`, `skills/` → `[FAIL]`
- [ ] Смоук-поиск перестал быть вакуумным: stderr не считается хитом, пустой результат
      → `[FAIL]`
- [ ] Коды возврата (0/1/2) и порядок проверок сохранены
- [ ] Проверка `.gitignore` покрывает все три строки, которых требуют правила
      (`.gitmark/`, `*-map.html`, `.scratch/`), оставаясь предупреждением (`exit 2`)
- [ ] Прогоны: в этом репо → `exit 0`; исправленный скрипт по плагинному пути с cwd
      потребителя в `sot-omp-marketplace` и `erp-demo` → `exit 0`; искусственно сломанный
      пакет (каталог команд/движка уведён) → `exit 1`
- [ ] `gitmark lint` чистый
